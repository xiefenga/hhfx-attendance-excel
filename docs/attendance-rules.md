# 考勤统计规则

本文档记录当前程序实际执行的固定考勤统计口径。规则以
`attendance_core/processor.py` 的实现为准，测试和输出工作簿均围绕这些规则工作。

> 说明：本文描述的是当前程序行为，不代表通用劳动考勤制度。尤其是“零次打卡”“一次打卡”等口径，使用前应由业务负责人确认。

## 1. 输入表结构

程序同时读取钉钉导出的“打卡时间”和“月度汇总”两个 `.xlsx` 文件。两张表的统计日期范围必须一致，人员通过钉钉导出表 F 列的 UserId 匹配。单边存在的人员会在界面警告，但仍保留该表能够提供的统计信息。首页按两张表的 UserId 并集生成：打卡表中的人员始终独立计算加班、迟到、旷工和餐补；月度表中的人员保留请假、旷工和每日考勤结果；能够匹配时合并两类数据。缺少或重复 UserId 会停止生成。

“打卡时间”表按以下固定位置解析：

| 位置 | 内容 |
| --- | --- |
| `A1` | 报表日期范围，识别形如 `YYYY-MM-DD` 的日期 |
| 第 4 行、G 列起 | 每日表头，用于判断工作日、周末或节假日 |
| 第 5 行起、A 列 | 姓名；为空时整行跳过 |
| 第 5 行起、C 列 | 部门 |
| 第 5 行起、D 列 | 工号 |
| 第 5 行起、F 列 | 钉钉 UserId |
| 第 5 行起、G 列起 | 每日打卡内容 |

“月度汇总”表读取 A、C、D、F 列人员信息、各类请假与旷工汇总列，以及“考勤结果”分组下的每日结果。它负责首页的请假统计和每天上午/下午状态；加班及餐补仍以“打卡时间”表为准。

日期从 `A1` 中识别出的报表开始日期起，按照 G、H、I……列逐日递增，不根据第 4 行的数字重新计算日期。

- 两张表的 `A1` 都必须包含两个日期，分别作为报表开始、结束日期。
- 日期范围缺失、日期无效或结束日期早于开始日期时停止生成。
- 打卡单元格可以包含其他文字；程序从中提取 `H:MM` 或 `HH:MM` 形式的合法时间。
- 相邻时间也能识别，例如 `08:3022:32外勤` 会解析为 `08:30`、`22:32`。
- 程序只处理 `.xlsx` 文件。

## 2. 统计范围和人员关联

程序始终使用源表标题中识别出的完整日期范围，边界日期均包含，不支持截取范围或忽略某些日期。

两张源表之间使用 F 列钉钉 UserId 关联同一个人；它只负责跨表数据合并，不要求人员必须同时出现在两张表中。加班明细内部仍以“姓名 + 部门 + 工号”的组合汇总。

生成结果中的“汇总人数”按两张表的 UserId 并集计算：同一 UserId 在两张表中只计 1 人，只存在于任意一张表中的人员也计入。

## 3. 日期类型识别

日期类型完全取决于源表第 4 行对应列的表头，不根据日期实际是星期几推断。因此可以正确表达周末补班。

| 第 4 行表头 | 日期类型 | 汇总分类 |
| --- | --- | --- |
| 空白或纯阿拉伯数字，如 `13` | 工作日 | 工作日 |
| `六`、`周六` | 周六 | 周末 |
| `日`、`周日` | 周日 | 周末 |
| `周末` | 周末 | 周末 |
| 其他非数字文本，如 `端午节`、`法假` | 保留原文本 | 节假日 |

非工作日是周六、周日、周末和节假日的统称。

## 4. 固定时间和金额规则

| 项目 | 固定值 | 当前用途 |
| --- | ---: | --- |
| 凌晨打卡截止 | `07:00` | 判断凌晨打卡归属；早于该时间才属于“截止前” |
| 上班时间 | `08:30` | 判断工作日迟到 |
| 加班起始时间 | `19:00` | 工作日进入加班判断的最低时间 |
| 2 小时加班阈值 | `21:00` | 工作日折算 2 小时加班 |
| 工作日餐补阈值 | `22:00` | 工作日出勤至该时间或更晚享受餐补 |
| 餐补金额 | `30` 元 | 每个符合餐补条件的日期计一次 |

这些规则不可在界面、sidecar 协议或命令行中调整。时间边界除“凌晨打卡截止”外均为包含关系。例如 `08:30` 不迟到，`21:00` 可以折算工作日加班 2 小时，`22:00` 可以获得工作日餐补。凌晨打卡必须严格早于 `07:00`；`07:00` 按当天打卡处理。

## 5. 打卡时间和跨天归属

程序先提取所有打卡时间，再把每条时间分配到一个“考勤归属日”。这一步会影响迟到、旷工、加班和餐补。

### 5.1 同一单元格中的跨天时间

如果一个日期单元格末尾连续出现早于凌晨截止时间的打卡，并且这些时间之前至少有一条不早于凌晨截止时间的打卡，则末尾的凌晨时间视为次日实际发生。

示例，凌晨截止为 `07:00`：

```text
6月26日单元格：07:30 01:54
解析时间：6月26日 07:30、6月27日 01:54
```

只有尾部连续的凌晨时间会滚到次日；普通的非时间顺序不会自动跨天。例如 `08:30 08:20 18:00` 都仍属于单元格对应日期。

### 5.2 凌晨时间分配到哪一个考勤日

对于实际发生时间早于凌晨截止的打卡，按以下顺序判断：

1. 如果当天存在一条“凌晨截止至上班时间之前”的正常上班打卡，则凌晨打卡归到前一天。
2. 否则，如果当天还有任意一条不早于凌晨截止的打卡，则凌晨打卡留在当天。
3. 否则，如果前一天在源数据中恰好只有一条打卡，则凌晨打卡归到前一天，用于补全前一天记录。
4. 其他情况留在当天。

这里的“正常上班打卡”范围为：`凌晨截止 <= 打卡时间 < 上班时间`。

## 6. 工作日规则

### 6.1 迟到

- 只判断工作日；周末和节假日不判断迟到。
- 在跨天归属完成后，取归属到该工作日且实际日期为当天的最早打卡。
- 最早打卡严格晚于上班时间时标记迟到。
- 最早打卡恰好等于上班时间不迟到。
- 没有当天打卡时，不会仅凭这一条件标记迟到。

固定上班时间为 `08:30`：

| 当天最早打卡 | 结果 |
| --- | --- |
| `08:29` | 不迟到 |
| `08:30` | 不迟到 |
| `08:31` | 迟到 |

### 6.2 旷工

当前程序采用以下特殊口径：

- 工作日归属打卡数量**恰好为 1 条**时，标记旷工；
- 工作日没有任何打卡时，当前实现不会生成记录，也不会标记旷工；
- 工作日有 2 条及以上打卡时，不标记旷工；
- 周末或节假日即使只有 1 条打卡，也不标记旷工。

工作日只有一条打卡时，程序不再计算该日加班和餐补。该日仍可能同时被标记迟到，例如唯一一条打卡晚于上班时间。

### 6.3 工作日加班和餐补

工作日有至少 2 条归属打卡且不属于“一次打卡旷工”时，根据最后打卡计算：

| 条件 | 折算加班 | 餐补 |
| --- | ---: | --- |
| 出勤至次日 `00:00` 及之后，且存在早于凌晨截止的有效跨天打卡 | 4 小时 | 有 |
| 无次日凌晨打卡，最后打卡 `< 19:00` | 0 小时 | 无 |
| 最后打卡 `19:00–20:59` | 0 小时 | 无 |
| 最后打卡 `21:00–21:59` | 2 小时 | 无 |
| 最后打卡 `>= 22:00` | 2 小时 | 有 |

时间段固定为上述规则。

当前工作日加班只会折算为 `0`、`2` 或 `4` 小时，不按实际分钟数计算：出勤至 `21:00` 且不到次日 `00:00` 折算 2 小时；出勤至次日 `00:00` 及之后，并存在符合跨天归属规则的凌晨打卡，折算 4 小时。只要折算为 4 小时就同时计餐补；同日出勤则需达到 `22:00` 才计餐补。

## 7. 周末规则

周六、周日和标记为“周末”的日期按小时计算加班。

程序以该考勤归属日的最早打卡和最后打卡组成出勤跨度。每个固定时段只有在出勤跨度完整覆盖该时段时才计入，不能按实际覆盖分钟数折算：

| 固定时段 | 计入条件 | 加班时长 |
| --- | --- | ---: |
| `09:00–12:00` | 最早打卡 `<= 09:00` 且最后打卡 `>= 12:00` | 3 小时 |
| `14:00–17:00` | 最早打卡 `<= 14:00` 且最后打卡 `>= 17:00` | 3 小时 |
| `17:00–21:00` | 最早打卡 `<= 17:00` 且最后打卡 `>= 21:00` | 2 小时 |

- 三个时段可累加，每天最多折算 8 小时。
- 打卡恰好落在时段开始或结束边界，可以覆盖该边界。
- 最早打卡落在一个时段内部时，该时段不计。例如 `10:00–13:00` 没有完整覆盖任何时段，计 0 小时。
- `10:00–17:00` 没有完整覆盖上午时段，但完整覆盖 `14:00–17:00`，计 3 小时。
- `08:30–18:00` 完整覆盖上午和下午时段，计 6 小时。
- `09:00–21:00` 完整覆盖三个时段，计 8 小时并享受餐补。
- 中间是否有打卡不影响计算；当前实现以最早、最后打卡形成的整体跨度判断，不扣除午休或中途离岗。
- 非工作日只有一条打卡无法完整覆盖任何时段，因此加班为 0 小时。

## 8. 节假日规则

除周末标记外的其他非数字日期表头按节假日处理，并以“天”为单位计算加班。时段覆盖判断与周末相同：最早打卡必须不晚于时段开始，最后打卡必须不早于时段结束。

| 固定时段 | 计入条件 | 加班天数 |
| --- | --- | ---: |
| `09:00–12:00` | 最早打卡 `<= 09:00` 且最后打卡 `>= 12:00` | 0.5 天 |
| `14:00–17:00` | 最早打卡 `<= 14:00` 且最后打卡 `>= 17:00` | 0.5 天 |

- 两个时段可累加，每天最多折算 1 天。
- `10:00–12:00` 没有完整覆盖上午时段，且没有覆盖下午时段，计 0 天。
- `10:00–17:00` 只完整覆盖 `14:00–17:00`，计 0.5 天。
- `09:00–12:00` 只完整覆盖上午时段，计 0.5 天。
- `09:00–17:00` 完整覆盖两个时段，计 1 天；实际跨度满 8 小时，享受餐补。
- `09:01–17:00` 只完整覆盖下午时段，计 0.5 天；实际跨度不足 8 小时，不享受餐补。
- 中间是否有打卡不影响计算；当前实现以最早、最后打卡形成的整体跨度判断。

## 9. 餐补规则

- 每个符合条件的考勤归属日计 1 次餐补。
- 每次固定 `30` 元。
- 工作日：最后打卡达到工作日餐补阈值，或存在符合规则的次日凌晨打卡。
- 周末：完整覆盖三个固定加班时段，累计折算满 8 小时。
- 节假日：最早打卡至最后打卡的实际跨度满 8 小时。
- 餐补总额 = 餐补次数 × 30 元。

## 10. 汇总表、明细和人员汇总

输出工作簿包含四张表，顺序固定如下。

### 10.1 汇总表

每名员工占上午、下午两行。工作日的标准时段为：

- 上午：`08:30–12:00`；
- 下午：`13:30–18:00`。

月度汇总表中的请假区间只要与某一标准时段有重叠，该半天即写对应假别（事假、病假、年假等）；正常、出差、外出和外勤均写 `√`，上班异常写迟到或缺卡，下班异常写早退或缺卡，无法细分时写“异常”。周末和节假日留空。首页同时汇总工作日加班小时、周末加班小时、节假日加班天数、各类请假、旷工、餐补和异常备注。仅存在于打卡表的人员也会追加到首页，其加班和餐补正常填写；由于没有月度源数据，请假、旷工及每日上下午状态留空。

### 10.2 加班明细

只输出至少命中以下一项的“人员 + 日期”记录：

- 工作日或周末加班时长大于 0；
- 节假日加班天数大于 0；
- 有餐补；
- 标记旷工；
- 标记迟到。

完全正常且无加班、无餐补的日期不会出现在明细中。字段包括人员信息、日期类型、原始打卡、最后打卡、折算加班时长、折算节假日加班天数、餐补、旷工、迟到和备注。

### 10.3 人员汇总

分别汇总：

- 加班日期；
- 旷工日期；
- 迟到日期；
- 餐补日期；
- 工作日和周末加班时长；
- 节假日加班天数；
- 工作日及周末加班总时长；
- 餐补次数和总金额。

没有加班、餐补、旷工和迟到的人员不会出现在人员汇总表中。

### 10.4 统计口径

在生成的 Excel 内附带主要规则说明，便于结果接收方查看。

程序返回的统计数字均基于“加班明细”中的异常或补贴记录，而不是源表所有人员日期的完整考勤台账。

## 11. 当前未实现或需要确认的规则

当前程序没有实现以下常见考勤概念：

- 零打卡自动判定旷工；
- 半天旷工或缺卡次数；
- 根据法定日历自动识别周末、节假日和补班；
- 按实际在岗分钟数计算加班；
- 使用“下班时间”判断早退或有效下班打卡；
- 排班、夜班、弹性工时和跨月班次；
- 重复打卡去重。

如果业务需要上述规则，应先明确口径，再同步修改业务核心、界面字段、输出说明和自动化测试。
